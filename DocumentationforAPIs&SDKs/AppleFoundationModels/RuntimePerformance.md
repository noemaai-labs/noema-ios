# Analyzing the runtime performance of your Foundation Models app

Use the Foundation Models instrument in Xcode to measure how prompts, responses, and tool calls affect performance.

Source: https://developer.apple.com/documentation/foundationmodels/analyzing-the-runtime-performance-of-your-foundation-models-app

## Overview

The Foundation Models instrument provides visibility into token consumption and response times while surfacing the prompts sent to models and where apps spend processing time. It offers insights into:

* Instructions, prompts, and responses for each model request
* Custom tool invocations, execution duration, and output
* Per-session breakdowns showing request timing and token consumption across steps

## Getting Started

1. Open Xcode and select **Product > Profile**
2. Choose the **Foundation Models** template
3. Click the **Record Trace** button to capture interactions

The instrument displays a timeline where "the width of each component on the timeline indicates latency."

## Token Monitoring

Tokens represent text fragments (typically words or word pieces). Key metrics:

* **Cache hit rate** — percentage of input tokens served from the KV prefix cache (divide cached input tokens by total input tokens)
* **Input tokens** — tokens from instructions, tools, schemas, and prompts
* **Output tokens** — tokens generated by the model
* **Reasoning tokens** (PCC only) — tokens used for intermediate reasoning in reasoning mode

High token counts affect both initial processing time and memory usage. Low cache hit rates between turns signal unexpected cache invalidation.

## Optimization Strategies via Instruments

### Reduce Schema Repetition

Setting `includeSchemaInPrompt` to `false` can reduce redundant schema information, potentially saving hundreds of tokens per request when making similar requests:

```swift
let stream = session.streamResponse(
    generating: Itinerary.self,
    includeSchemaInPrompt: false  // skip re-sending schema after first turn
) {
    "Generate a 3-day itinerary to Yosemite."
}
```

### Identify Cache Invalidation Points

Use the instrument to spot where the cache is being invalidated unnecessarily. Compare cached vs. total input tokens across turns. When the cache hit rate drops to near zero between turns, something changed in the prefix (instructions, tool list, etc.).

### Measure Tool Call Overhead

The instrument shows each tool invocation's execution duration and output. Use this to identify slow tools that add latency to the model's response chain.

### Profile First-Turn Latency

Use `prewarm(promptPrefix:)` to eliminate first-turn cold-start latency:

```swift
// Called when you know usage is 1–2+ seconds away
session.prewarm(promptPrefix: "Help me with")
```

The instrument shows whether the prewarm completed before the first request arrived.

## Debugging with the Inspector Panel

The inspector panel shows detailed token breakdowns and duration metrics for each request:

* Full instruction text sent to the model
* Prompt text as received
* Model response text
* Tool call details including arguments and return values
* Token count per component
